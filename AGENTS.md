# SubManager — правила проекта

Дополняет глобальный `~/.kimi-code/AGENTS.md`. При конфликте важнее этот файл.

## Стили

- SCSS пишется строго по БЭМ: `.block__element--modifier`.
- Блок = имя компонента в kebab-case (`.sub-card`, `.toast`, `.form-field`).
- Запрещены плоские классы вида `.top`, `.logo`, `.nm` — только элементы блока.
- Стили компонента лежат в его же папке и содержат только его блок.
- Общие keyframes — в `client/src/shared/styles/animations.scss`.

## Структура кода

- Страница — тонкий композиционный слой (~100 строк): только стейт и сборка виджетов.
- Разметка секций — в виджетах `client/src/widgets/<Name>/`.
- Логика — в хуках: `shared/lib/` для переиспользуемого, `features/<name>/model/` для фич.
- Один файл — одна ответственность; файлы на 500+ строк запрещены.

## Git

- Коммиты только после явного одобрения пользователя. После каждого этапа — спрашивать, коммитить ли.

## Роадмап (зафиксировано с пользователем)

Старт каждого этапа — только по явной отмашке пользователя.

1. **Офлайн-режим (PWA)** — следующий этап: IndexedDB через Dexie.js, очередь синхронизации в Service Worker, PWA-манифест и install prompt, досинхронизация с Supabase при появлении сети.
2. **Техдолг**: code-splitting бандла (612 кБ), проверка светлой темы на всех экранах, конвертация валют в сообщениях бота, тесты + CI/CD.
3. **View Transitions API** на переходы между табами — только если выйдет плавнее текущих CSS-анимаций.

Вычеркнуто навсегда: парсинг форвардов ботом (создание подписок из пересланных сообщений) — не делаем.
