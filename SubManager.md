## ПРОЕКТ SubManager

Техническое задание (ТЗ): Платформа управления подписками и шеринга расходов (SubManager)1. Описание проектаSubManager — это кроссплатформенное веб-приложение (PWA + Telegram Mini App), предназначенное для учета регулярных подписок, финансовой аналитики и автоматического сбора средств (split) с участников совместных подписок через Telegram.Концепция: Приложение спроектировано по принципу Graceful Degradation (постепенной деградации). Оно полноценно работает как независимый веб-сервис с базовой авторизацией (Email/Google), но раскрывает максимальный потенциал (автоматические рассылки должникам) при привязке Telegram-аккаунта.2. Технологический стек2.1. Клиентская часть (Frontend)Фреймворк: React.Язык: TypeScript (строгая типизация API ответов и стейтов).Управление состоянием: Redux Toolkit (в связке с RTK Query для кэши
рования и работы с API).Стилизация: SCSS-модули + CSS-переменные для темизации.Локальное хранилище (Офлайн): IndexedDB (через библиотеку Dexie.js).Анимации: Framer Motion (для View Transitions и интерактивных карточек).2.2. Серверная часть (Backend & Bot)Среда: Node.js (TypeScript).Архитектура: Serverless функции (REST API).Telegram Bot API: Библиотека grammY или Telegraf.База данных и Auth: Supabase (PostgreSQL). Бесплатный тариф покрывает нужды БД и встроенную аутентификацию.2.3. ИнфраструктураХостинг клиента и API: Vercel.Фоновые задачи (Cron): GitHub Actions. Использование триггера on: schedule для бесплатного ежедневного запуска скриптов проверок и рассылок.3. Архитектура Авторизации и ДанныхСистема поддерживает гибкую авторизацию без дублирования аккаунтов. В таблице пользователей поля email и telegram_id независимы.Вход через Веб-браузер (Desktop / Mobile)Используется стандартная авторизация Supabase: Email + Пароль или OAuth (Google).Пользователь имеет доступ ко всем функциям трекера, кроме автоматической рассылки Split-уведомлений друзьям (эта функция блокируется с предложением привязать Telegram).Вход через Telegram Mini App (TMA)Бесшовная авторизация. Фронтенд передает серверу initData от Telegram.Сервер валидирует хэш, извлекает telegram_id и пускает пользователя в приложение, генерируя JWT-токен.Связывание аккаунтов (Account Linking / Deep Linking)Алгоритм предотвращения создания дублей при привязке Telegram к уже существующему веб-аккаунту:Авторизованный (по Email) веб-пользователь заходит в настройки и нажимает «Привязать Telegram».Фронтенд запрашивает у API уникальный одноразовый токен (например, link_A1B2C3), который сохраняется в БД (срок жизни 15 минут).Пользователь перенаправляется в бота по ссылке вида: t.me/SubManagerBot?start=link_A1B2C3.Бот получает команду /start, находит токен в БД и привязывает свой telegram_id к существующему id пользователя.4. Пользовательские сценарии (User Journeys)Сценарий 1: Офлайн-работа и синхронизация (PWA)Пользователь (ранее авторизованный) открывает приложение без интернета (например, в метро).UI загружается мгновенно из кэша Service Worker.Данные о подписках читаются из локальной IndexedDB.Пользователь добавляет новую подписку. Она сохраняется в IndexedDB, а в очередь Service Worker падает задача на синхронизацию.При появлении интернета фоновый процесс (Background Sync) отправляет данные на бэкенд (Supabase).Сценарий 2: Добавление подписки (Магия пресетов)Пользователь нажимает кнопку +.Появляется Bottom Sheet с иконками популярных сервисов.При выборе пресета (например, "Netflix"), форма предзаполняется цветом бренда и средней ценой.Пользователь указывает дату следующего списания и сохраняет карточку.Сценарий 3: Настройка сплит-оплаты (Требуется Telegram)Пользователь открывает детали подписки "Spotify Family" и жмет "Разделить оплату".Вводит @username друга в Telegram и сумму его доли.Бэкенд создает запись в таблице Splits.Сценарий 4: Ежедневные Cron-рассылки должникамЕжедневно в 10:00 GitHub Actions дергает Serverless-эндпоинт /api/cron/reminders.Бэкенд ищет списания на завтра, у которых есть участники в таблице Splits со статусом pending.Бот рассылает должникам сообщения с Inline-кнопкой: [Я перевел].При нажатии кнопки должником, владелец подписки получает уведомление об оплате, а статус в БД и интерфейсе меняется.Сценарий 5: Умный мониторинг и добавление через парсинг в TelegramПользователь пересылает боту чек/SMS из банка (например: "Списание 399 руб Yandex Plus").Сервер с помощью регулярных выражений извлекает сумму и название.Бот спрашивает: "Добавить Яндекс Плюс (399 руб) в трекер?". Две кнопки: "Да" / "Нет".Если подписка уже существует, но цена изменилась, бот предупреждает: "Яндекс Плюс подорожал. Обновить цену в трекере?".5. Структура интерфейса (UI Layout)Главный дашборд:Крупный виджет: "Всего расходов в этом месяце".Анимированный кольцевой график распределения по категориям.Горизонтальная лента "Ближайшие списания" (Timeline) с датами и логотипами сервисов.Сетка карточек (Grid/Masonry) всех активных подписок с эффектами Glassmorphism.Экран аналитики:Кастомный селектор дат. На клиенте алгоритм скользящего окна мгновенно пересчитывает сумму на основе IndexedDB.Фильтры по категориям (формируются динамически через структуру Set).Настройки профиля:Управление авторизацией (привязка Telegram / Email).Настройка базовой валюты отображения.6. Структура Базы Данных (Supabase / PostgreSQL)ТаблицаОписаниеПоляUsersПользователи системыid (UUID), email (String, nullable), telegram_id (BigInt, nullable), currency (String)LinkTokensТокены связывания аккаунтовtoken (String), user_id (FK), expires_at (Timestamp)SubscriptionsЗаписи о подпискахid (UUID), user_id (FK), title (String), amount (Decimal), next_payment_date (Date), color_hex (String)SplitsДолжники совместных подписокid (UUID), subscription_id (FK), debtor_username (String), amount (Decimal), status (Enum: pending, paid)CategoriesСправочник категорийid (UUID), name (String), icon_url (String)7. Этапы разработки (Roadmap)MVP Клиента (PWA & UI): Инициализация React-приложения, настройка Redux Toolkit, верстка дашборда и логики работы с IndexedDB. Создание пресетов.Auth & Backend: Настройка Supabase. Реализация авторизации (Email + Telegram Login Widget). Разработка базовых CRUD-операций через REST API.Telegram Bot & Account Linking: Разработка логики бота (grammY). Создание системы Deep Linking для склейки аккаунтов. Настройка парсинга сообщений (форвардов).Сплит-система и Cron: Настройка таблицы должников. Создание GitHub Actions пайплайна для ежедневных проверок БД и триггера рассылок.Деплой и полировка: Релиз на Vercel. Добавление View Transitions API для бесшовных анимаций интерфейса. Тестирование работы внутри TMA.
